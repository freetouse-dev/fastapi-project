# Step 8: User Model & First Database Migration

## 1. Overview
In this step, we defined our foundational `User` ORM model using modern SQLAlchemy 2.0 type mapping (`Mapped` and `mapped_column`), registered it with the metadata catalog, generated an autogenerated migration script via Alembic, and applied it to the MySQL database.

---

## 2. Concepts Learned

### 2.1 Entity Design: The User Model
A production user entity requires:
- `id`: Auto-incrementing primary key index.
- `email`: Indexed, unique constraint for fast authentication lookups.
- `hashed_password`: Stores cryptographic hashes instead of plaintext passwords.
- `is_active`: Flag to soft-deactivate accounts without breaking relational integrity (e.g., tasks or comments previously authored by this user).
- `is_superuser`: System-level admin flag.
- `created_at` / `updated_at`: Server-managed audit timestamps generated and updated automatically by MySQL via `func.now()`.

### 2.2 Modern SQLAlchemy 2.0 Syntax
- Uses typed mapping (`Mapped[T]`) for compile-time and IDE type safety.
- Explicit `mapped_column(..., nullable=False)` ensures clear column definitions.

### 2.3 Alembic Autogeneration Workflow
1. The model is registered in `models/__init__.py`.
2. `alembic/env.py` imports `project_management_api.models` so Alembic can discover the entities on `Base.metadata`.
3. `alembic revision --autogenerate -m "..."` compares the Python models against MySQL tables and emits migration commands.
4. `alembic upgrade head` executes DDL (`CREATE TABLE users`, indexes) inside MySQL.
